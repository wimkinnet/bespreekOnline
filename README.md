# bespreekOnline

A CRM built for a school & school-pool advisory consultancy: clients (schools /
school pools), assignments with variable billing rates, document & bill
uploads per client/assignment, and manual time registration (hourly, daily,
or tracked-only for fixed-fee work). Built with React (Vite), Node/Express,
MongoDB, and designed to deploy to Render as a single web service.

## How it's organized

```
bespreekOnline/
  server/      Express API + serves the built React app in production
    models/    Mongoose schemas: User, Client, Assignment, TimeEntry, Document
    routes/    REST endpoints
    middleware/ auth (JWT + roles), file upload (multer)
    uploads/   local file storage in dev (gitignored)
  client/      React app (Vite)
    src/pages/       one file per screen
    src/components/  layout & route guards
    src/context/     auth state
  render.yaml  Render Blueprint (one web service + a persistent disk)
```

## Core concepts

- **Roles.** `admin` (you, and any partners you promote) manages clients,
  assignments, rates and consultant accounts. `consultant` (people you hire)
  can view clients/assignments they're staffed on, log their own time, and
  upload documents. Only admins can create/edit clients and assignments or
  change rates.
- **Assignments carry the rate.** Each assignment has a `billingType`
  (`hourly`, `daily`, or `fixed`) and a `rate`. A time entry snapshots the
  rate that was active when it was logged, so changing an assignment's rate
  later never rewrites historical entries.
- **Time registration** is manual entry only: pick an assignment, a date, and
  hours or days (whichever the assignment's billing type calls for).
  Fixed-fee assignments can still log days for internal tracking, but the
  billed amount lives on the assignment itself, not on each entry.
- **Documents & bills** are uploaded per client, optionally linked to a
  specific assignment, and categorized as "document" or "bill". Files are
  stored on disk under `UPLOAD_DIR/<clientId>/...` — see the storage note
  below before deploying.

## Local setup

You'll need Node 18+ and a MongoDB connection string. The free tier of
[MongoDB Atlas](https://www.mongodb.com/atlas) works well and is what most
small consultancies use with Render, since Render itself doesn't offer a
managed MongoDB.

1. **Backend**

   ```bash
   cd server
   cp .env.example .env
   # edit .env: paste your MONGODB_URI, set a real JWT_SECRET,
   # and set SEED_ADMIN_EMAIL / SEED_ADMIN_PASSWORD to your own login
   npm install
   npm run seed     # creates your first admin account, run once
   npm run dev       # starts the API on http://localhost:5000
   ```

2. **Frontend** (in a second terminal)

   ```bash
   cd client
   npm install
   npm run dev       # starts on http://localhost:5173, proxies /api to :5000
   ```

3. Open `http://localhost:5173` and log in with the admin email/password you
   set in `.env`.

4. As admin, go to **Consultants** to create accounts for the people you
   hire, then **Clients** → add a school or school pool → **Assignments** to
   add billable work with its rate and billing type, and assign consultants
   to it so they can log time.

## Deploying to Render

This is set up to run as **one Render web service** that serves both the API
and the built React app — simplest to operate for a small team.

1. **Push this project to a GitHub repo** (the `.gitignore` already excludes
   `node_modules`, `.env`, and local uploads).

2. **Set up MongoDB Atlas**: create a free cluster, a database user, and
   allow network access from anywhere (`0.0.0.0/0`, since Render's IPs
   aren't static on the starter plan). Copy the connection string.

3. **In Render**, choose "New +" → "Blueprint" and point it at your repo —
   it will read `render.yaml` and configure the service, including a 1GB
   persistent disk mounted at `/var/data` for uploaded documents. When
   prompted, fill in:
   - `MONGODB_URI` — your Atlas connection string
   - `SEED_ADMIN_EMAIL` / `SEED_ADMIN_PASSWORD` / `SEED_ADMIN_NAME` — only
     needed if you run the seed script via Render's shell afterwards (see
     step 5)
   - `JWT_SECRET` is auto-generated by the blueprint; leave it as is.

   If you'd rather set it up manually instead of via Blueprint: create a
   **Web Service**, build command
   `cd client && npm install && npm run build && cd ../server && npm install`,
   start command `node server/server.js`, add a disk mounted at `/var/data`,
   and set `UPLOAD_DIR=/var/data/uploads` plus the env vars above.

4. **Deploy.** Render will build the client, then start the Express server,
   which serves the built frontend and the API from the same URL and port.

5. **Create your first admin account** using Render's Shell tab on the
   service (Dashboard → your service → "Shell"):

   ```bash
   cd server && npm run seed
   ```

   This reads `SEED_ADMIN_EMAIL`/`SEED_ADMIN_PASSWORD`/`SEED_ADMIN_NAME` from
   the environment and creates the account once. After that, use the
   **Consultants** page in the app to create everyone else — there's no
   public sign-up screen by design.

### A note on the persistent disk

You chose Render's persistent disk for document/bill storage, which is the
simpler option and works well at your scale. Two things worth knowing:

- Render's paid persistent disks aren't automatically backed up — export or
  snapshot the disk periodically (Render supports manual disk snapshots on
  paid plans), or keep a copy of important bills elsewhere.
- A disk is tied to a single service instance, so this setup won't scale
  horizontally (multiple server instances) — not a concern for a small
  consultancy, but worth knowing if you grow a lot. If that ever changes,
  swapping `middleware/upload.js` to use an S3-compatible bucket instead of
  local disk is a contained change.
